Calls to Private Clubs cost nothing. This page covers the data license, bulk data, how the API pages results, the rate limit headers and the limits on the MCP server.

## Pricing

Calls to the Private Clubs MCP server and API are free, with no account or API key needed. Bulk access to the directory is a paid data feed license, as [Bulk data](#bulk-data) explains. Searching, saving, comparing and enquiring with clubs on theprivateclubs.com are free too.

Business plans for clubs, brands and creators are on the [pricing page](https://www.theprivateclubs.com/pricing).

## Data license

The [data license](https://www.theprivateclubs.com/data/license) and section 8 of the [terms of service](https://www.theprivateclubs.com/legal/terms) set what you may do with Private Clubs data. You may use the MCP server and the API as documented, at no charge, to look up, search and compare clubs and to show the results inside an AI app or product, including for work. When you show results, credit Private Clubs as the source and link to the club's profile on theprivateclubs.com. The data license gives the attribution format.

## Bulk data

Bulk access is a paid monthly data feed license. You need one to download the directory in bulk, extract it systematically, scrape, mirror, cache or store the directory or a substantial part of it, build or enrich a database or dataset with it, train AI models on it or resell it. Paging through results or splitting up queries to collect the directory counts as bulk use, and so does any use that works around the rate or result limits. Private Clubs may limit, suspend or block access that looks like bulk collection.

To ask about a data feed license, email support@theprivateclubs.com. See the [data license](https://www.theprivateclubs.com/data/license) and the [terms of service](https://www.theprivateclubs.com/legal/terms).

## API page size

| Parameter | Default | Rules |
|---|---|---|
| `page` | 1 | Starts at 1. `page` times `limit`, with `limit` clamped to 50, can be at most 500, and a larger product returns 403 `data_feed_required`. A value that is not a whole number from 1, such as `0`, returns 400 `invalid_page`. Leading zeros are fine, and an empty `page=` counts as not sent. |
| `limit` | 50 | The maximum is 50, and larger values are clamped to 50. A value that is not a whole number from 1, such as `0`, returns 400 `invalid_limit`. Leading zeros are fine, and an empty `limit=` counts as not sent. |

The API returns the first 500 results of a search. Stop paging when `page * limit` reaches `total` or 500, whichever comes first. A page past the last result, within the first 500, returns 200 with an empty `clubs` array and the real `total`. A page that reaches past result 500 returns 403 with `data_feed_required` whatever the `total`, even when `total` is below 500.

## Rate limit headers

Every API response sends these two headers:

```text
RateLimit: limit=120, remaining=119, reset=60
RateLimit-Policy: 120;w=60
```

They advertise a policy of 120 requests per 60 seconds. Keep within 120 requests a minute. The values are the same on every response, so do not read `remaining` as a live count.

If a request fails with a 500 or 503, wait and retry with backoff.

## MCP limits

| Limit | Value |
|---|---|
| Request body | 2 MB |
| Messages in one batch | 100 at most |
| `initialize` | Sent on its own, never in a batch |
| `search_clubs` results | Up to 25, with no paging |
| `get_clubs_by_state` results | Up to 100 |
| `compare_clubs` slugs | 2 or 3 |
| Slow or failed requests | A 503 with `Retry-After: 10` when a request runs past 50 seconds or fails inside the server |

The MCP server has no request rate limit. When a search needs more than 25 or 100 clubs, use the API, which returns up to 50 clubs a page and the first 500 results of a search. See [Troubleshooting](/mcp/troubleshooting) for the exact error messages.
